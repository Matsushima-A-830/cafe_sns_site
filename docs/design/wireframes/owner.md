# カフェ経営者画面

サブターゲットである経営者向けの画面群。認証済みユーザー（`profiles.role = 'owner'`）のみ利用可能。

## S_OWNER_CLAIM（オーナー認証申請）

`S_CAFE_DETAIL` の「このカフェのオーナーですか?」から遷移。

### モバイル

```
+----------------------------------------+
| [<戻る]  オーナー認証申請              |
+----------------------------------------+
| 対象カフェ                              |
| ┌──────────────────────────────────┐  |
| │ [サムネ] {カフェ名}              │  |
| │         渋谷区                   │  |
| └──────────────────────────────────┘  |
+----------------------------------------+
| 認証されると:                            |
| ● 公式バッジが表示されます              |
| ● 店舗情報を編集できます                |
| ● 投稿分析ダッシュボードにアクセス      |
| ● ユーザーとのコミュニケーション        |
+----------------------------------------+
| 提出書類（以下から2点以上を選択）       |
|                                        |
| [ ] 営業許可証（画像）                  |
|     [ ＋ アップロード ]                |
|                                        |
| [ ] 屋号入り名刺 + 店舗内で撮影した     |
|     本人写真（2枚）                     |
|     [ ＋ アップロード ]                |
|                                        |
| [ ] Googleビジネスプロフィール連携      |
|     ※オーナー確認済アカウント必須     |
|     [ 連携する ]                       |
|                                        |
| [ ] 法人登記簿（法人経営の場合）        |
|     [ ＋ アップロード ]                |
|                                        |
| [ ] 開業届（税務署受領印付き）          |
|     [ ＋ アップロード ]                |
+----------------------------------------+
| 選択済み: 0 / 2 必要                    |
+----------------------------------------+
| 連絡先メール                            |
| < ______________________ >             |
+----------------------------------------+
| 補足事項 (省略可能)                     |
| < ______________________ >             |
| 例: 屋号と本人氏名が異なる場合の説明等 |
+----------------------------------------+
| [ ] 提出情報は本人のものです           |
| [ ] 審査結果に従います                  |
| [ ] 運営から追加確認の連絡がある場合    |
|     があることを理解しました            |
+----------------------------------------+
| [申請を送信する]         (primary)     |
| ※ 2点未選択の場合は送信不可           |
+----------------------------------------+
```

- 書類アップロードは Supabase Storage 非公開バケット
- チェックボックス3つを必須にすることで摩擦を意図的に上げる（悪意ある申請への抑止）
- 「Googleビジネスプロフィール連携」は OAuth 相当のフローで実装（技術的検討事項）
- 選択2点未満は「申請を送信する」ボタン disabled

## S_OWNER_REGULARS（常連認定管理）

**⭐️ 幹C:** オーナーが顧客に「常連さん」バッジを付与・管理する画面。ダッシュボードからアクセス。

### モバイル

```
+----------------------------------------+
| [<戻る]  常連さん管理                  |
+----------------------------------------+
| 現在の常連: 12名                        |
+----------------------------------------+
| ┃常連┃ 認定候補 認定履歴                | <- タブ
| ─────                                  |
+----------------------------------------+
| ┌────────────────────────────────┐   |
| │ [アバター] {ユーザー名}          │   |
| │ 投稿 8 · コメント 12             │   |
| │ 認定: 2026年8月10日              │   |
| │ メモ: いつもありがとうございます  │   |
| │              [メモ編集] [取消]   │   |
| └────────────────────────────────┘   |
| ┌────────────────────────────────┐   |
| │ [アバター] {ユーザー名}          │   |
| │ ...                              │   |
| └────────────────────────────────┘   |
+----------------------------------------+
```

### 認定候補タブ

**選定基準:** 自店へ複数回投稿、または頻繁にコメントしてくれるユーザーをアプリ側で抽出。

```
+----------------------------------------+
| 常連 ┃認定候補┃ 認定履歴                |
| ─────                                  |
+----------------------------------------+
| 自店に投稿・コメントが多い方           |
+----------------------------------------+
| ┌────────────────────────────────┐   |
| │ [アバター] {ユーザー名}          │   |
| │ 投稿 12 · コメント 8 · 保存 3   │   |
| │ 最終来店: 3日前                  │   |
| │              [常連認定 ▶]        │   |
| └────────────────────────────────┘   |
| ...                                    |
+----------------------------------------+
```

### 認定モーダル

```
+----------------------------------------+
|                                        |
|   {ユーザー名} を常連認定しますか？    |
|                                        |
|   認定すると、ユーザーの「行きつけ」   |
|   一覧にこのカフェが強調表示されます。 |
|   ユーザーには通知が届きます。         |
|                                        |
|   一言メモ（任意）                      |
|   < 例: いつもありがとうございます   >|
|                                        |
|         [キャンセル]  [認定する]       |
|                                        |
+----------------------------------------+
```

### 取消モーダル

```
+----------------------------------------+
|                                        |
|      認定を取り消しますか？             |
|                                        |
|   ユーザーには通知されません。         |
|   履歴には残ります。                    |
|                                        |
|         [キャンセル]  [取消する]       |
|                                        |
+----------------------------------------+
```

- 取消は `regular_customers.revoked_at` を設定（DELETE ではなく履歴保持）

### 認定履歴タブ

- 過去の全認定・取消履歴（時系列）
- 「常連ランキング」的な分析はフェーズ2以降

### PC版

```
+----------------------------------------------------------------------------------+
| ヘッダー                                                                          |
+---------+------------------------------------------------------+-----------------+
| ダッシュ | 常連さん管理                現在の常連: 12名        | 統計            |
| ボード  +------------------------------------------------------+ 今月新規認定: 3 |
| ● 常連 | ┃常連┃ 認定候補 認定履歴                            | 平均訪問頻度: 週2|
|         +------------------------------------------------------+                |
|         | ┌ユーザーカード┐┌ユーザーカード┐┌ユーザーカード┐  |                |
|         | └──────────────┘└──────────────┘└──────────────┘  |                |
+---------+------------------------------------------------------+-----------------+
```

### 実装メモ

- 認定/取消は `regular_customers` テーブルの INSERT / UPDATE (`revoked_at` 設定)
- 認定候補の抽出クエリは Postgres 関数化（RPC）
- 認定時に `notifications.type = 'regular_awarded'` を発火
- 通知本文例: 「{カフェ名} から常連さん認定を受けました！」

## 経営者フロー共通の注意

- 経営者が自分の店に**なりすまし投稿を放置しない**ため、通報導線（`S_REPORT_FORM`）は経営者側からも使えるようにする
- 認証済みバッジは信頼の根幹なので、**認証取消フロー**（利用規約違反時）も後日設計が必要
- MVPスコープ: 公式投稿・クーポン配布は含めない（フェーズ2以降）
