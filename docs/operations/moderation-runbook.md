# モデレーションランブック

通報・削除依頼への一次対応手順。検証ベータ運用中は運営者（matsu120a40@gmail.com）が単独で対応する前提。
`docs/product/pending-items.md D67` の決定に基づき最小構成で用意する。

## 通報キュー（S_ADMIN_REPORTS）

- 対象: ユーザーが通報フォーム（S_REPORT_FORM）経由で提出した投稿・コメント・ユーザー・カフェ
- 確認場所: `/admin/reports`（status=`pending` が未対応）
- **目標対応時間: 提出から48時間以内に `reviewing` へ着手、7日以内に `resolved`/`rejected` を確定**
  （検証ベータは小規模運用のため、この数値は実際の通報量を見て[pending-items.md](../product/pending-items.md)で見直す）
- 判定の選択肢は `lib/constants/admin-reports.ts` の `REPORT_DECISIONS` を参照
  （`minor_risk`（未成年に不適切）の通報は他より優先して着手する）

## 削除依頼（第三者からの削除請求）

- 対象: `/takedown` ページ経由でメール（matsu120a40@gmail.com）に届く、著作権者等からの削除請求
- ユーザーの通報とは別導線（ログイン不要・本人以外からの請求を想定）
- 対応手順:
  1. 依頼内容（対象URL・理由・連絡先）を確認する
  2. 対象の投稿/コメント/画像を特定し、権利侵害の訴えが一見して理由があるか確認する
  3. 妥当と判断したら `/admin/reports` の判定アクション（`hide_post`/`delete_comment`）と同等の操作で非表示化する
     （通報キューに起票されていない対象のため、Supabase管理画面またはadmin API経由での直接操作になる）
  4. 依頼者に対応結果を返信する
- **目標対応時間: 7日以内に一次回答**

## 停止・削除の基準

- `suspend_user`（ユーザー停止）は、繰り返しの違反・未成年への危害リスク・法令違反の疑いが明確な場合に限定する
- 判断に迷うケースは機械的に処理せず、一旦 `reviewing` のまま保留してよい（検証ベータ中は件数が少ないため急がない）

## 検証ベータ終了後の見直し

本公開に向けて通報量が増える場合、複数人体制・SLA再設定・エスカレーション先の明文化が必要になる
（[pending-items.md D66](../product/pending-items.md#d66-利用規約プライバシーポリシーは専門家レビュー未了のドラフト)の有料法務相談と合わせて見直す）。
